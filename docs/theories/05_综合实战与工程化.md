# 综合实战与工程化 (Engineering & Best Practices)
- 自动化测试：Unit Test、Widget Test、Integration Test 三者的覆盖侧重点是什么？
    -  Unit Test（单元测试）
        - 侧重点：验证单一的代码块（函数、方法或类）的纯逻辑是否正确。
        - 测试对象：数据模型（Models）、状态管理逻辑（如 Redux Reducers、Bloc、ViewModel）、工具类函数（Utils）、算法等。
        - 核心特征：
        - 极度隔离：不涉及 UI 渲染，不依赖真实的外部环境（网络、数据库），外部依赖通常会被模拟（Mock）。
        - 执行速度极快：通常在毫秒级，可以在每次保存代码时运行。
        - 高覆盖率：占据测试金字塔的底层，数量最多。
        - 典型场景：
            - 输入密码“123”，验证 isValidPassword() 函数是否返回 false。
            - 调用 fetchUserData() 后，验证 JSON 数据是否被正确解析成了 UserModel 对象。

    - Widget Test / Component Test（组件测试）
        - 侧重点：验证单一 UI 组件的渲染、布局以及用户交互逻辑。
        - 注：“Widget Test”是 Flutter 的专有名词，在 React/Vue 中称为组件测试（Component Test），在原生 iOS/Android 中通常归类为轻量级的 UI 测试。
        - 测试对象：单个按钮、复杂的列表项（ListTile）、自定义的弹窗、或者一个独立的页面（不涉及页面跳转）。
        - 核心特征：
            - 环境模拟：不需要启动完整的应用程序，而是在一个虚拟的、无头的（Headless）环境中渲染 UI 组件。
            - 关注交互与状态：主要测试“用户的操作（如点击、滑动）是否引起了预期的 UI 变化”。
            - 执行速度适中：比单元测试慢（因为涉及渲染树构建），但远快于集成测试。
            - 典型场景：
                - 向 CustomButton 传入 isLoading: true，验证界面上是否渲染了加载小菊花，且文字被隐藏。
                - 模拟用户点击“提交”按钮，验证是否正确调用了传入的 onPressed 回调函数。

    - Integration Test（集成测试）
        - 侧重点：验证多个模块组合在一起时，甚至是整个应用的端到端（End-to-End, E2E）工作流是否正常。
        - 测试对象：完整的业务流程（如登录流程、购物车结算流程）。
        - 核心特征：
        - 真实环境：必须在真实的设备（真机）或模拟器（Emulator/Simulator）上运行。它会像真实用户一样启动完整的 App。
        - 覆盖链路长：包括 UI 渲染、页面路由跳转、甚至是真实的（或部分 Mock 的）网络请求和本地数据库读写。
        - 执行速度最慢、维护成本最高：占据测试金字塔的顶端，因为一旦 UI 发生微小变动或网络延迟，测试就容易失败（即“脆弱的测试”）。
        - 典型场景：
        - 主链路验证：启动 App -> 在输入框输入账号密码 -> 点击登录按钮 -> 等待网络请求返回 -> 验证是否成功跳转到了首页（Home Screen） -> 验证首页是否展示了用户的真实昵称。

- CI/CD 集成：如何利用 GitHub Actions 实现 Flutter 的自动化构建与分发？
    - 1. 准备工作：提取并转码签名文件
        - GitHub Actions 无法直接读取你的本地 Keychain，因此我们需要将签名文件转换为 Base64 字符串存入 GitHub Secrets。
        - 导出证书：从 Keychain 导出 Apple Distribution 证书为 Certificates.p12（记得设置密码）。
        - 下载描述文件：从 Apple Developer 网站下载对应的 profile.mobileprovision。
        - 转换为 Base64：在终端执行以下命令，将生成的一大段字符串分别复制备用。
        ```bash
            base64 -i Certificates.p12 | pbcopy
            base64 -i profile.mobileprovision | pbcopy
        ```
        - 准备 ExportOptions.plist：在 Flutter 项目的 ios/ 目录下准备一个 ExportOptions.plist 文件（指定 method 为 app-store，以及对应的 provisioningProfiles 键值对）。

    - 2. 配置 GitHub Secrets
        - 进入你的 GitHub 仓库 -> Settings -> Secrets and variables -> Actions，添加以下机密变量：
            - BUILD_CERTIFICATE_BASE64：上面生成的 .p12 Base64 字符串。
            - P12_PASSWORD：导出 .p12 时设置的密码。
            - BUILD_PROVISION_PROFILE_BASE64：上面生成的描述文件 Base64 字符串。
            - KEYCHAIN_PASSWORD：随便设置一个密码（用于在 Action 运行时创建临时钥匙串）。
            - APPSTORE_ISSUER_ID：App Store Connect API 的 Issuer ID。
            - APPSTORE_API_KEY_ID：App Store Connect API 的 Key ID。
            - APPSTORE_API_PRIVATE_KEY：App Store Connect 下载的 .p8 秘钥内容。

    - 3. 编写 GitHub Actions 工作流
        - 在项目根目录创建文件 .github/workflows/ios_deploy.yml。以下是核心的 YAML 配置模板：
        ```yaml
        name: iOS CD - Build and Distribute to TestFlight

        # 触发条件：当你打上 'v' 开头的 tag 时触发（如 v1.0.0）
        on:
        push:
            tags:
            - 'v*'

        jobs:
        build-and-deploy-ios:
            # 必须使用 macOS 运行环境
            runs-on: macos-latest

            steps:
            - name: 📦 Checkout code
                uses: actions/checkout@v4

            - name: 🍎 Install Apple Certificate and Provisioning Profile
                env:
                BUILD_CERTIFICATE_BASE64: ${{ secrets.BUILD_CERTIFICATE_BASE64 }}
                P12_PASSWORD: ${{ secrets.P12_PASSWORD }}
                BUILD_PROVISION_PROFILE_BASE64: ${{ secrets.BUILD_PROVISION_PROFILE_BASE64 }}
                KEYCHAIN_PASSWORD: ${{ secrets.KEYCHAIN_PASSWORD }}
                run: |
                # 创建临时变量存放证书和描述文件路径
                CERTIFICATE_PATH=$RUNNER_TEMP/build_certificate.p12
                PP_PATH=$RUNNER_TEMP/build_pp.mobileprovision
                KEYCHAIN_PATH=$RUNNER_TEMP/app-signing.keychain-db

                # 从 Base64 还原文件
                echo -n "$BUILD_CERTIFICATE_BASE64" | base64 --decode -o $CERTIFICATE_PATH
                echo -n "$BUILD_PROVISION_PROFILE_BASE64" | base64 --decode -o $PP_PATH

                # 创建临时钥匙串
                security create-keychain -p "$KEYCHAIN_PASSWORD" $KEYCHAIN_PATH
                security set-keychain-settings -lut 21600 $KEYCHAIN_PATH
                security unlock-keychain -p "$KEYCHAIN_PASSWORD" $KEYCHAIN_PATH

                # 导入证书到钥匙串
                security import $CERTIFICATE_PATH -P "$P12_PASSWORD" -A -t cert -f pkcs12 -k $KEYCHAIN_PATH
                security list-keychain -d user -s $KEYCHAIN_PATH

                # 安装描述文件 (移动到特定目录下供 Xcode 读取)
                mkdir -p ~/Library/MobileDevice/Provisioning\ Profiles
                cp $PP_PATH ~/Library/MobileDevice/Provisioning\ Profiles

            - name: 🐦 Setup Flutter
                uses: subosito/flutter-action@v2
                with:
                channel: 'stable'
                cache: true

            - name: 📦 Install Dependencies
                run: flutter pub get

            - name: 🔨 Build iOS IPA
                # 使用 --export-options-plist 告诉 xcodebuild 如何进行签名和导出
                run: flutter build ipa --release --export-options-plist=ios/ExportOptions.plist

            - name: 🚀 Upload to TestFlight
                # 使用第三方高质量 Action 调用 App Store Connect API 上传
                uses: apple-actions/upload-testflight-build@v1
                with:
                # Flutter 构建的 ipa 默认路径
                app-path: build/ios/ipa/Runner.ipa
                issuer-id: ${{ secrets.APPSTORE_ISSUER_ID }}
                api-key-id: ${{ secrets.APPSTORE_API_KEY_ID }}
                api-private-key: ${{ secrets.APPSTORE_API_PRIVATE_KEY }}

            - name: 🧹 Clean up keychain and provisioning profile
                if: ${{ always() }}
                run: |
                    # 清理机密文件，防止泄露
                    security delete-keychain $RUNNER_TEMP/app-signing.keychain-db
                    rm ~/Library/MobileDevice/Provisioning\ Profiles/build_pp.mobileprovision
        ```

- 国际化与本地化：如何处理动态语言切换及 RTL（从右向左阅读）布局适配？
    - 核心基础：基于 .arb 文件的官方方案
        - 现代 Flutter 国际化的标准做法是使用 flutter_localizations 和 .arb (Application Resource Bundle) 文件。这种方式会在编译时自动生成强类型的 Dart 类（通常是 AppLocalizations），让你在代码中通过 AppLocalizations.of(context)!.helloWorld 来安全地调用词条。
    - 二、 如何实现“无缝”的动态语言切换？
        - 在应用内提供一个按钮，点击后立即切换全站语言且不重启应用，核心在于使用状态管理来驱动 MaterialApp 的 locale 属性重建。
        - 无论你使用的是什么状态管理工具，基本架构模式如下：
            - 1. 创建一个全局的语言状态控制器
                - 我们需要一个能够持久化保存用户选择（如使用 shared_preferences），并在改变时通知 UI 的类。
            ```Dart
            import 'package:flutter/material.dart';

            class LocaleProvider extends ChangeNotifier {
                Locale? _locale;

                Locale? get locale => _locale;

                void setLocale(Locale locale) {
                    if (!L10n.all.contains(locale)) return; // L10n.all 是你在 arb 中配置的支持列表
                    _locale = locale;
                    notifyListeners();
                    // TODO: 将选择持久化保存到本地存储
                }

                void clearLocale() {
                    _locale = null; // 设为 null 将跟随系统语言
                    notifyListeners();
                }
            }
            ```
    - 2. 将状态注入到 MaterialApp
        - 在顶层挂载你的状态，并将 locale 传递给 MaterialApp。当 LocaleProvider 发出通知时，MaterialApp 会带上新的 locale 重建整个应用的 Widget 树。
        ```Dart
        // 假设使用 Provider 作为状态管理
        Consumer<LocaleProvider>(
            builder: (context, provider, child) {
                return MaterialApp(
                title: 'Global App',
                // 1. 挂载当前选中的 Locale
                locale: provider.locale, 
                // 2. 声明支持的语言列表
                supportedLocales: AppLocalizations.supportedLocales,
                // 3. 挂载本地化代理
                localizationsDelegates: AppLocalizations.localizationsDelegates, 
                home: const HomePage(),
                );
            }
        )
        ```
    - 三、 攻克 RTL (从右向左) 布局适配
        - Flutter 的 UI 系统默认就对 RTL 有着极好的支持。当 MaterialApp 的 locale 被切换为 RTL 语言（如 ar）时，框架内部的 Directionality 环境变量会自动翻转。
        - 为了让你的 UI 完美适配，你需要遵守以下几个“戒律”：
        - 1. 彻底抛弃 Left / Right，拥抱 Start / End
            - 这是最重要的思想转变。就像 iOS 原生的 leading/trailing，在 Flutter 中，涉及到方向、边距、对齐的属性，全部改用带有 Directional 后缀的类。
            - 内边距 / 外边距：
                - ❌ EdgeInsets.only(left: 16)
                - ✅ EdgeInsetsDirectional.only(start: 16)
            - 对齐方式：
                - ❌ Alignment.topLeft
                - ✅ AlignmentDirectional.topStart
            - 绝对定位：
                - ❌ Positioned(left: 10, ...)
                - ✅ Positioned.directional(textDirection: Directionality.of(context), start: 10, ...)
            - 圆角裁剪：
                - ❌ BorderRadius.only(topLeft: Radius.circular(8))
                - ✅ BorderRadiusDirectional.only(topStart: Radius.circular(8))
            - 当你使用 Directional 类时，当语言切换为阿拉伯语时，start 会自动从屏幕左侧变为屏幕右侧，无需你写任何 if-else。

        - 2. 处理具有方向性的图标
            - 像返回箭头（←）这种图标，在 RTL 模式下应该翻转变成（→）。Flutter 的 Icon Widget 提供了一个极其方便的属性：
            ```Dart
                Icon(
                    Icons.arrow_back,
                    matchTextDirection: true, // 开启后，在 RTL 环境下图标会自动水平镜像翻转
                )
            ```
            - 注意：并非所有图标都需要翻转（例如时钟、对勾 ✔️ 通常不需要），只有涉及“方向指示”的才需要开启此属性。

        - 3. 处理复杂的自定义绘图与动画
            - 如果你在应用中使用 CustomPaint 画了一些高度自定义的不对称图形，或者包含平移动画，你需要手动读取当前环境的方向来决定渲染逻辑：
            ```Dart
                final isRTL = Directionality.of(context) == TextDirection.rtl;
            ```

        ```Dart
        import 'package:flutter_riverpod/flutter_riverpod.dart';

        // 1. 定义 Notifier
        class LocaleNotifier extends Notifier<Locale?> {

                // 返回 null 表示跟随系统语言
                return null; 
            }

            // 2. 暴露修改状态的方法
            void setLocale(Locale locale) {
                // 状态(state)是不可变的，直接重新赋值即可触发监听者重建
                state = locale; 
                
                // TODO: 持久化保存到本地 (SharedPrefs / Hive)
            }
        }

        // 3. 声明全局 Provider
        final localeProvider = NotifierProvider<LocaleNotifier, Locale?>(() {
            return LocaleNotifier();
        });

        import 'package:flutter/material.dart';
        import 'package:flutter_riverpod/flutter_riverpod.dart';

        void main() {
            // 必须用 ProviderScope 包裹根节点
            runApp(const ProviderScope(child: MyApp()));
        }

        class MyApp extends ConsumerWidget {
            const MyApp({super.key});

            @override
            Widget build(BuildContext context, WidgetRef ref) {
                // 监听语言状态。当 state 改变时，只有这个 build 方法会重新执行
                final currentLocale = ref.watch(localeProvider);

                return MaterialApp(
                title: 'Web3 App',
                locale: currentLocale, // 绑定状态
                supportedLocales: AppLocalizations.supportedLocales,
                localizationsDelegates: AppLocalizations.localizationsDelegates,
                home: const HomePage(),
                );
            }
        }
        ```
